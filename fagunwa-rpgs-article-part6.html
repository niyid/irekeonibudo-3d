The Wiring

Where Each Idea Actually Attaches

Every item the earlier draft listed as a comment now has a real anchor point — a class, a call, a line in SceneSetupWizard.cs that runs it. Here's where each one landed, checked directly against the source.

Riddle pools
RiddleGiver.cs now carries an optional RiddlePool field; if assigned, Start() calls RiddlePool.PickIndex() for a weighted, anti-repeat draw instead of using the fixed inspector fields. SceneSetupWizard builds and assigns a dedicated pool asset per spirit type — OstrichKingRiddlePool/ArogidigbaRiddlePool for the bosses, GhommidRiddlePool/MotherSpiritRiddlePool for the wanderers.
Wisdom-gated difficulty
RiddleGiver.EffectiveMinDifficulty() raises the difficulty floor — not just the ceiling — as WisdomTracker.currentWisdom climbs past configurable thresholds, capped so it never exceeds that spirit's own maxDifficulty. A ghommid stays lighter than the boss even at high wisdom.
Stat variance
CreatureStatRoller.RollVariance(), called right after CreatureAI.ApplyPreset() in the wizard — nudges health/speed/damage/aggro-range ±15% per instance without disturbing the tuned baseline between creature types.
Procedural placement
ProceduralSpiritPlacer.GeneratePositions() scatters ghommid/mother-spirit spawn points inside WorldBounds' band with minimum clearance from each other and from creature spawns; JitterPosition() adds smaller variance around creatures' hand-authored staging so their order is preserved but their exact spot isn't.
Bounds struct
WorldBounds replaced ExpeditionManager's standalone villageBoundaryZ float and the duplicated min/max literals in the wizard with one struct, read from both places — OgbojuOdeDefaults and IrekeOnibudoDefaults are the only per-story difference in an otherwise identical file.
Reproducible seed
RunSeed.NewRandom(streamName) is now called from every procedural site — riddle picks, stat rolls, placement, dialogue branching — each keyed by its own stream name so systems don't correlate with each other, all derived from one playthrough seed set via RunSeed.Initialize().
Dialogue pools
DialogueTree (branching weighted lines) + DialogueSpeaker (auto-fires on proximity, walks the tree) replace the old single fixed line per ghommid/mother-spirit-guide. Wired via GetOrCreateGhommidChatter()/GetOrCreateMotherSpiritChatter() in the wizard.
Codex / persistence
WisdomTracker now owns Save()/Load() over PlayerPrefs, plus seenRiddles/seenCreatureTypes sets keyed by riddle text (stable across pool reshuffles) rather than pool index — cross-session anti-repeat and journal data in one place.
Accessibility
MobileTouchUI.interactButton is now wired to TryInteractWithNearbyRiddleGiver(), calling RiddleGiver.Interact() directly — the F-key path's touch equivalent, previously missing entirely on mobile.
One File, Now Actually Wired

RunSeed.cs — This Is What "Wired In" Looks Like

RunSeed is the clearest example of the gap between the marked version and the built one. It doesn't just exist in isolation anymore — every procedural system asks it for a named stream, so a riddle pick, a stat roll, and a spirit placement in the same playthrough are each independently random but still reproducible from a single seed.

RunSeed.cs — full file, both repos, byte-identicalC#
public static class RunSeed { public static int Value { get; private set; } private static bool initialized = false; public static void Initialize(int? forcedSeed = null) { Value = forcedSeed ?? System.Guid.NewGuid().GetHashCode(); initialized = true; Debug.Log($"[RunSeed] Playthrough seed: {Value}"); } public static System.Random NewRandom(string streamName) { if (!initialized) Initialize(); int combined = Value ^ streamName.GetHashCode(); return new System.Random(combined); } }

No caller has to remember to seed anything — NewRandom() auto-initializes on first use, and every stream is combined with the playthrough value via a distinct streamName ("riddle_<spirit>", "creature_<id>", "dialogue_<id>") so no two systems draw from the same sequence. That's the difference this entry is actually about: not a better comment at the call site, but the call itself.

Roadmap

What's Actually Left

Shorter list than either previous draft implied. The procedural layer is done; what remains is mostly UI and content, plus one verification step that hasn't happened on either project yet.

Riddle UI
Still the actual biggest gap — RiddleGiver.Interact() logs the riddle and auto-resolves as correct rather than showing a real prompt-and-answer screen. Everything upstream of the UI (pool, difficulty gating, codex) is ready for it to attach to.
Unity Editor compile check
Neither project has been opened in the Editor since these changes landed. The scripts reference each other in enough directions — RiddleGiver → RiddlePool → WisdomTracker → RunSeed, SceneSetupWizard → all of the above — that a typo'd reference could still be sitting there uncaught.
Dialogue UI
DialogueSpeaker logs lines to the console the same way RiddleGiver logs riddles; a real dialogue box for ambient chatter is the equivalent gap on that side.
Animation, HUD, Audio, save-file format
Unchanged from Part V — still open in both projects. Wisdom/codex now persist via PlayerPrefs, but a real save-file format for fuller game state is still ahead.
Conclusion

The Only Source Of Truth Is The Diff

Five parts in, this series was mostly about proving an architecture travels — that a script written for one Fagunwa book keeps working, unmodified, when pointed at another. This entry, rewritten twice now, is a smaller and less comfortable proof: that a description of work drifts from the work itself in both directions if nobody checks against the actual files each time — first by claiming too much, then by correcting to too little after the correction was already out of date. The fix isn't a better summary at either extreme. It's diff, git log, and reading the files that exist right now, every time this gets written down. That's what this version is.
